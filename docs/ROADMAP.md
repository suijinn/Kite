# Kite ロードマップ

当初の要件に対する達成状況と、未実装項目の優先順位。
設計の全体像は [architecture.md](architecture.md)、機能ごとの判断理由と踏んだ罠は
リポジトリ直下の [CLAUDE.md](../CLAUDE.md) を参照。

**完了した項目の詳細はこの文書に残さない。** 何をどう決めたかは CLAUDE.md の該当節が、
今の構造は architecture.md が書いている ─ ここに写しを置くと、次に直したとき片方だけが
古くなる。残すのは「終わった」という事実と、参照先だけ（§3）。

凡例: ✅ 完了 / 🟡 部分的 / ⬜ 未着手
規模感: **S** = 1 日以内 / **M** = 数日 / **L** = 1〜2 週 / **XL** = それ以上

現在の版は 0.1.15。テストは 30 スイート・887 件。

## 4. 残っている項目

### フェーズ 1 — 安定性

#### P1-6. 終了時の保存失敗を伝える — **S**

**現状、終了時の `SaveAll()` が失敗しても誰にも見えない。** `WM_CLOSE` → `App::Shutdown` →
`SaveAll()` の戻り値は捨てられ、ステータス行はもう描かれない（CLAUDE.md「設定の置き場所」）。
書けない場所に展開すれば初回起動の `keys.ini` で必ず露見するので実用上は気付けるが、
**「一度書けた場所が後から書けなくなった」場合だけが漏れる** ─ 設定を変えたつもりで
消えている、という一番たちの悪い形。

手当ての候補は 2 つ。(1) 起動時に設定フォルダへの書き込み可否を 1 回試して言う。
(2) `Shutdown()` が失敗を返し、`WinWindow` が OS のメッセージボックス（platform 側なので
`IHost` を広げなくてよい）で「閉じる／戻る」を訊く。**(2) のほうが正直**だが、× を押したのに
閉じないのは説明が要る。単独ウィンドウは何も書かないので対象外。

### フェーズ 2 — エクスプローラー機能パリティ

#### P2-4. サムネイル — **M**

`IThumbnailCache` / `IShellItemImageFactory` を**必ず別スレッドで、`kite_shellhost.exe` の
中で**呼ぶ（サムネイルハンドラもサードパーティの in-proc DLL）。`ui::Renderer::DrawIcon`、
`IIconProvider` / `IconCache`、ホストとの画素のやりとり（重複排除・世代管理）は P2-10 で
できているので、**要求に種別とサイズを足して同じ経路に乗せる** ─ 画素の経路を 2 本に
しない。クラウドのプレースホルダには要求しない（ダウンロードが走る）。ホストの
時間制限（8 秒）とアイドル終了はそのまま効く。

#### P2-5. 表示形式の切替 — **M**

詳細（現行）／一覧／中アイコン／大アイコン。`AppUi::PaintList` は行を前提に組んであるので、
枠（`slots`）の数え方を «1 行 1 枠» から «格子» へ広げる形になる。**P2-4 の後**にする ─
サムネイルの無い大アイコン表示は、ベクタ描画の絵が並ぶだけで意味を持たない。
表示形式は `ViewState` に持ち、P3-13 でタブごとに残す。

#### P2-7. プレビューウィンドウ — **M**

`IPreviewHandler` はサードパーティコードなので**自プロセスには入れない**。
`kite_shellhost.exe` に 4 つ目の役を足し、ホスト側のウィンドウを Kite の子として貼るか、
ビットマップを共有メモリで受け取る。ペイン分割がすでにあるので、置き場所は
«フォーカス中のペインの右» で足りる ─ 独立した帯を設けない。**画像・テキスト・PDF の
3 つで検索結果を開かずに確かめられれば、P2-3 の価値が一段上がる。**

#### P2-8b. ネットワーク全体の参照 — **M**（条件付き）

`\\` そのものを開いてドメイン／ワークグループとサーバーを列挙する話。`WNetOpenEnum` に
`lpRemoteName = nullptr` を渡し、返ってきたコンテナをもう 1 段展開する ─ **が、これは
コンピューターブラウザーサービスに依存する**。SMB1 とともに既定で無効化されて久しく、
今の Windows では数十秒待たされた末に空が返ることのほうが多い。**待たせて空を返す
機能は、無い機能より悪い。** 入れるならタイムアウトと「探索中」の表示が先で、それでも
入れる価値があるかは要検討。P2-1 の「ネットワーク」（SSDP 中心のシェル名前空間）とは
別物。

#### P2-9. ドライブの安全な取り外し — **S**

サイドバーのドライブの右クリックから。`CM_Request_Device_Eject`。取り外しの前に
そのドライブを見ているタブがあれば、一覧を捨てて親（「PC」）へ逃がすこと ─ 監視の
ハンドルが残っていると取り外しが断られる。

#### P2-12. 書庫の中で右クリックの「開く」「プログラムから開く」「プロパティ」を効かせる — **S**

3 つとも今はシェルに素通しする経路で、書庫の中では**中身の入っていないファイル**が渡る
（CLAUDE.md「書庫をフォルダとして開く」の表）。`Enter` とダブルクリックだけは Kite が
`IFileOperation` で取り出してから開くので効く。

- メニューの既定項目が選ばれたことをホストが `InvokeCommand` せず **`kite.exe` へ返し**、
  `App::ActivateEntry` と同じ経路に流す ─ **開き方を 2 通りにしない。**
- `IShellIntegration::OpenWith` と `ShowProperties` に `Open()` と同じく `folder` を取らせ、
  `"openas"` / `"properties"` を `InvokeVerb` へ回す。

#### P2-13. 既定のファイルマネージャーの実機検証 — **S**（検証）

`Folder\shell\open\command` を上書きする今の版で、**デスクトップとエクスプローラーの
窓の中でフォルダをダブルクリックしたときに Kite が開くかを実機で確かめていない**
（CLAUDE.md「現時点の弱点」の先頭）。「エクスプローラーを置き換える」という目標の
最後の 1 経路なので、結果を先に知っておく。

取れなかった場合、シェルのビューはフォルダを自分のプロセスの中で開いている ─
レジストリの動詞を通っていない ─ ということで、残る道は explorer.exe に読み込まれる
DLL しかない。**その道は採らない**（§5）ので、取れなければそれがこの機能の限界として
README に書く。

### フェーズ 3 — 操作性

#### P3-13. タブごとの表示設定の永続化 — **S** ★最優先

**今は保存していない。** `sessions.ini` に残るのはセッション名・分割レイアウト・タブの
パスだけで、読み込み時は全タブの `ViewState` が既定値（`App::defaultView_`）で塗り直される
（`App::LoadWorkspace`）。名前順に並べ替えて隠しファイルを出したタブは、次の起動で元に戻る
─ **毎回の起動で確実に気付く不便**で、P3-14 の «サイズで並べる» もこれが無いと残らない。

エクスプローラーは**フォルダごと**に覚えるが、Kite が覚えるべきなのは**タブごと** ─
同じフォルダを 2 つのペインで別の並びで見るのは分割ファイラーの日常で、フォルダに紐付けると
その 2 枚が取り合う。`Session::Serialize()` にソート・降順・フォルダ先頭・隠しファイル・
塊の 5 つを足す。**列の並びと幅は対象外** ─ あれは «一覧の読み方» でウィンドウに 1 つ
（CLAUDE.md「一覧の列」）。

- **古い `sessions.ini` を読めなくしないこと。** レイアウト文字列の書式を変えるので、
  項目が無ければ既定値、という読み方にする。
- P2-5 の表示形式も同じ器に載る。

#### P3-11. スクロールバーのドラッグと、長い一覧での選択の枠 — **S**

スクロールバーは表示だけで掴めない ─ 一覧の脇のものも、縦置きタブバー・`F1`・チューザ・
キー設定の細いつまみ（`AppUi::PaintThinScrollbar`）も同じ。**掴めるようにするなら
全部まとめて** ─ 隣り合った帯の片方だけが動くのは学びにくい。当たり判定は `Region` に
`Hit::ScrollThumb` を足し、ドラッグは `Drag` の 1 種として同じ流儀で扱う。

掴めるようにすれば、その帯を「選択の枠を引ける余白」から外している理由
（`AppUi::BeginMarquee`）も消える。そのうえで枠を一覧の端から引けるようにすると、
全行が収まらない一覧でも枠が使える。そこまで行くと**枠の自動スクロールが初めて意味を
持つ** ─ ポインタが枠外で止まったままではマウスイベントが来ないので、`WinWindow` 側に
一定間隔のタイマーを足して `AppUi` を叩く形になる（`kStatusTimerId` と同じ作り）。

#### P3-15. 入力欄のクリックでキャレットを動かす — **S**

どの入力欄も、クリックは «その打鍵はそこで終わる» だけでキャレットは動かない
（CLAUDE.md「対象の上で編集する」の末尾）。パスの途中を直したい人が `←` を連打している。
**入れるときは全部の入力欄に同時に入れる** ─ アドレスバー・名前の変更・新規作成・
セッション名・チューザの絞り込み欄は全部 `TextField` 1 つと `AppUi::PaintTextField`
1 か所なので、当たり判定に文字の x 座標を持たせて `TextField::SetCaret` を呼ぶだけで
5 か所に効く。`Shift+クリック` は選択の伸縮（`anchor` を据え置く）。ダブルクリックで
パスの 1 区切りを選ぶのは `Ctrl+←→` と同じ単位で。

#### P3-5. クイックアクセスのピン留め編集 — **S**

並びだけは覚えている（`quickAccessOrder_`）が、外す・足すは無い。エクスプローラーの
「クイックアクセスにピン留め」と同じ場所（`shell:::{679f85cb-…}` の項目）を書くか、
Kite の側で «隠す» 一覧を持つかの 2 択。**前者ならエクスプローラーと同じ顔ぶれのまま、
後者なら Kite だけの並び。** ブックマークがすでに «利用者が留めたもの» なので、
Kite 独自の集合をもう 1 つ持つ理由は薄い ─ 前者を推す。

#### P3-2. 2 打鍵キーシーケンス — **S**

`Chord` は拡張できる形にしてある（`Keys.h` の `@todo`）。`KeyMap` を「1 打鍵目で待機状態に
入る」構造に変え、`keys.ini` の記法を `Ctrl+K Ctrl+\` 形式に拡張する。待機中は
ステータス行に 1 打鍵目を出す（型入力ジャンプの打ちかけと同じ理由 ─ 画面が何も変わらない
ので、出さないと «キーが効かない» と見分けが付かない）。

#### P3-16. 既定の和音の移動を、既存の `keys.ini` に伝える — **S**

`keys.ini` は全コマンドを書き出すので、**既定を動かしても既存環境には届かない**
（`Ctrl+N`、`Ctrl+P` で 2 度踏んだ罠 ─ CLAUDE.md「2 枚目のウィンドウ」「行き先の一覧」）。
「既定の上に足す」に戻すのは誤り（CLAUDE.md「`keys.ini` は書かれたとおりに読む」）なので、
代わりに `keys.ini` の見出しに**書いた版**を残し、起動時にその版より後で既定が動いた
コマンドがあれば、**ファイルの値が旧既定のままのものだけ**ステータス行で言う
（「`nav.places` の既定は `Ctrl+P` に移りました」）。書き換えはしない ─ 利用者が
わざわざ旧既定に戻していたのかもしれない。

### フェーズ 4 — 性能とメモリ

#### P4-1. メモリ削減（約 66 MB → 40 MB 台）— **M**

内訳の実測がまだ。**先に計測すること。推測で削らない。** 想定される手当: D3D11 デバイスの
遅延生成と非アクティブ時の解放、`fs::Entry` の SoA 化（現在は 1 件あたり `std::string` を
持つ）、DirectWrite のフォントキャッシュ調整。描画経路の割り当て削減（`string_view`、
文字幅の写しの 2 世代化）は済んでいるので、残っているのはグラフィックスタックの側。

#### P4-2. 巨大ディレクトリ対応 — **M**

10 万件クラスでの列挙・ソート・描画。列挙結果のストリーミング表示（全件揃う前に描き
始める）と、ソートの並列化。先に 10 万件のフォルダで実測し、どこが待ち時間なのかを
出してから。

#### P4-3. 起動時間の実測と短縮 — **S**

現状の計測は `Start-Process` 経由でプロセス生成込みのため誤差が大きい（145〜320 ms）。
アプリ内に計測点を仕込んで内訳（DLL ロード / D3D 初期化 / 設定読み込み / 初回列挙）を出す。

## 5. あえてやらないこと

判断を蒸し返さないための記録。詳細は CLAUDE.md の各節。

- **リボン UI / コマンドバー / メニューバー。** キーボード駆動を主軸に据えたので不要。
  設定は `Ctrl+,` のオーバーレイ 1 枚、実行は `Ctrl+Shift+P` のパレット。
- **ファイル操作の自前実装。** コピー・移動・削除はシェル（`SHFileOperation`）に委ねる。
  進捗表示・競合解決・ごみ箱連携を自前で書き直すのは、ファイラーがデータを失う最も
  一般的な原因。呼ぶ場所だけは UI スレッドから外した（`FileOpQueue`）。
- **ファイル操作の中断。** シェルに始めさせた操作を外から止める手段が無い。進捗ダイアログの
  「キャンセル」はシェル自身のものなので、そちらは今までどおり効く。
- **シェルアイコンの同期取得。** `SHGetFileInfo` は 1 行ごとにクラウドプロバイダを呼ぶ。
  要件 3・13 と正面から衝突する。
- **explorer.exe に読み込まれる DLL。** エクスプローラーの窓の中でフォルダを開く経路を
  取るにはこれしか無いが（P2-13）、サードパーティのコードを自プロセスに入れない方針と
  逆向きに、Kite のコードを他人のプロセスに入れることになる。
- **プラグインシステム。** 当面。サードパーティコードを自プロセスに入れるのは、
  P1-1 / P2-10 / P2-1 で追い出した方針と正面から逆行する。
- **サードパーティライブラリの導入。** 起動時間・配布サイズ・ビルドの単純さを優先する。
  テストハーネスを自作しているのもこの方針の一貫。
- **Windows Search のインデックスと、全文検索。** 張られていないフォルダで黙って 0 件を
  返す検索は無い機能より悪い。中身を探すにはインデックスが要り、それは «自前で歩けば
  どこでも同じ答えが出る» という今の作りの外にある。
- **塊（グループ化）の折り畳み。** 畳んだ状態を覚える先が要るが、塊は並べ替えを変える
  たびに別物になる。代わりに件数を見出しに出す。
- **フォルダのサイズでハードリンクを畳む。** ファイル ID の集合を常駐させることになり、
  数十万件でその代金のほうが高い。
- **2 枚目以降のウィンドウの状態保存。** 別プロセスなので、後から閉じたほうが本体の
  変更を古い内容で上書きする。残したい配置は元のウィンドウで作る。
- **`App` のさらなる分割。** 外に出せる «葉»（フォルダのサイズ・検索）は出した。残っている
  入力欄・ファイル操作・チューザは判断ではなく配線で、切るには «出来事» を受け取る口の
  設計から始めることになる（architecture.md §2）。形だけの分割はしない。
- **オーナードローのメニュー項目をダークにする。** TortoiseGit などが自前の配色で描く
  項目は `SetShellMenuDarkMode` に従わない（`ShellMenu.h` の `@todo`）。拡張の側の
  描画に手を入れる道は無い。
- **コード署名。** 有料なので採らない。Defender の誤検知には `.sha256` を添えて報告する。

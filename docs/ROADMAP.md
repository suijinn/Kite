## 3. フェーズ 1 — 安定性（最優先）

要件 13 の残課題と、常用に入る前に潰しておくべきもの。

### P1-1. シェル拡張の別プロセス化 `kite_shellhost.exe` — ✅ 完了

`IContextMenu` のハンドラ（Box、Google Drive、7-Zip、TortoiseGit …）は
`kite_shellhost.exe` の中だけで動く。拡張が確保したメモリを壊しても、裏でスレッドを
立てて落ちても、失われるのはメニュー 1 回分とホストプロセスだけ。次の要求で黙って
起動し直す。これで要件 13 が埋まった。

構成は `ShellHostProtocol.h`（交換する書式。Windows 非依存で `tests/test_hostproto.cpp`
が直接検証）、`ShellPipe.cpp`（名前付きパイプ）、`ShellHostClient.cpp`（`kite.exe` 側）、
`ShellMenu.cpp`（`IContextMenu` 本体。**ホストだけがリンクする**）、
`tools/shellhost/main.cpp`（ホストの入口）。

core / ui 側の変更は `IShellIntegration` の戻り値が `void` から `bool` になった
（メニューを出せなかったことを status 行に出す）だけ。設計上の判断は CLAUDE.md の
「シェル拡張の隔離」、残っている制限は同「現時点の弱点」。

### P1-2. 元に戻す（Ctrl+Z）— ✅ 完了

`Ctrl+Z`（`Cmd::Undo`）が、**名前の変更・新規作成・移動・コピー・ごみ箱への削除**を
元に戻す。履歴は `core/app/UndoStack`（OS にも描画にも触れない）が持ち、逆操作は
`App::DoUndo` が `IFileSystem`（削除だけは `IShellIntegration`）を通して行う。
`tests/test_undo.cpp` が端から端まで検証する。

**シェル任せにはできなかった。** `FOF_ALLOWUNDO` はシェルの Undo スタックに積むが、
そこを呼ぶ公開 API が無い。加えて名前の変更は `MoveFileExW` なので、そもそもそのスタックに
載らない ─ シェル任せにすると「F2 で付けた名前を戻す」という一番よく要る操作が
最初から対象外になる。

**ごみ箱への削除は戻せる。** 履歴が覚えるのは**消される前のパス**で、ごみ箱の中で
名乗る `$R` の名前ではない ─ 削除の時点で分かっているのがそちらしかなく、控えるには
削除のたびにごみ箱を引き当て直すことになって、一度も `Ctrl+Z` を押さない人まで
その代金を払うことになる。突き合わせは戻すときに 1 回だけ行い、「元の場所」
（`PID_DISPLACED_FROM`）と項目名から元のパスを組み立てて比べる。同じパスの項目が
複数あれば**最後に消したもの**を採る（`PID_DISPLACED_DATE`）─ `Ctrl+Z` が指している
のは常に直前の削除なので、それが正しい答えになる。

**完全削除だけは戻せない。** 履歴に「戻せない印」（`UndoKind::Erase`）を積み、`Ctrl+Z`
はそこで止まって理由を言う ─ 飛び越えると、消えたファイルはそのままにその前の
名前変更だけが巻き戻る。**ごみ箱への削除ではこの印を積まない**（戻せる以上、その下の
操作が到達不能になる理由が無い）。設計上の判断は CLAUDE.md の「元に戻す」と
「`Ctrl+Z` で削除を戻す」。

### P1-3. 単一インスタンス化 — ✅ 完了

2 つ目の起動は、既存のウィンドウへパスを渡して自分は黙って終わる。パスは
そのウィンドウの新しいタブになり、ウィンドウが前面に出る。目印（ミューテックス名と
ウィンドウクラス名）は **exe のフルパスから導く**ので、別フォルダに展開した 2 つの
コピーは別のインスタンスとして動く ─ 固定名にすると、一方の `config` だけが使われる
（CLAUDE.md「設定の置き場所」）。

`--new-window` が付いた起動だけがこの検出を通らない。`Ctrl+N`（`Cmd::NewWindow`）が
使うのがこの引数で、今や「本当に新しい窓が要る」と言える唯一の手段。

| ファイル | 役割 |
| --- | --- |
| `platform/win/WinSingleInstance.cpp` | 目印の生成、既存ウィンドウの探索、`WM_COPYDATA` の送受形式 |
| `src/main_win.cpp` | 起動時の振り分け |
| `App::OpenForwardedPaths` | 受け取ったパスをタブとして開く |

設計上の判断は CLAUDE.md の「単一インスタンス」。

### P1-4. エラー処理の網羅 — ✅ 完了

**失敗は必ず言う。** 名前の変更・作成・削除・コピー・移動・元に戻すは、失敗したら
何が失敗したかをステータス行に出す（`App::ReportFailure`）。以前は OS の文言を
そのまま流していたので、`ErrorText()` が文言を持たないコードでは**何も出ないまま
操作だけが失敗した** ─ 画面が何も変わらないので「キーが効かない」と読める。
設計上の判断は CLAUDE.md の「失敗の伝え方」。

| 潰したもの | どうしたか |
| --- | --- |
| アクセス拒否フォルダ | 一覧はエラー行を出し、`..` も出さない。UNC なら `Ctrl+Shift+L` を案内 |
| ロック中ファイルのリネーム | 「名前を変更できませんでした」＋ OS の文言。履歴には積まない |
| 260 文字超のパス | 規則を `path::ToExtended()`（core）へ移して検証。**拡張パスには OS の正規化が掛からない**ので、付ける前に `Normalize()` を通す |
| 列挙中のドライブ切断 | `FindNextFileW` が落ちたら**半分の一覧を捨てる**。デバイス系のコードを `Unavailable` に振る |
| オフラインのクラウドフォルダ | `ERROR_CLOUD_FILE_*` を `Unavailable` / `AccessDenied` に振る。空のフォルダとして出さない |
| シェル操作の失敗 | `SHFileOperation` の `DE_*` を Win32 コードへ写して OS の言葉で出す。利用者の取り消しは失敗にしない |

検証は `tests/test_app.cpp`（失敗の伝わり方）、`tests/test_pathutil.cpp`（拡張パス）、
`tests/test_utf8.cpp`（UTF-16 換算の長さ）。`FakeFileSystem::locked` が、
OS が何も言わない失敗を含めて再現する。

## 4. フェーズ 2 — エクスプローラー機能パリティ

要件 6 を埋める。ここまで来ると「常用してエクスプローラーを無効化できる」水準。

### P2-1. 仮想フォルダ（「PC」「ごみ箱」「ネットワーク」）— ✅ 完了

3 つともサイドバーの先頭に並び、開いて辿れる。「PC」からドライブへ入れば普通のフォルダ
（`C:\`）になり、`Alt+↑` で戻れば「PC」に出る ─ `\\server` の上が「ネットワーク」に
なるのも同じ規則（`vfs::ParentOf`）。名前空間拡張が作る入れ子のフォルダ（iCloud フォト
など）もそのまま開ける。

`WinShellFileSystem` を別に立てるのではなく、`WinFileSystem::List` が `virtual:` の付いた
パスだけを振り分ける形にした。**実 FS の高速経路には一切触れていない。** `fs::Entry` に
足したのは PIDL ではなく `address` という文字列 1 本で、実フォルダの項目では空のまま ─
10 万件のフォルダで 1 件ずつ std::string を増やす代償を払わない。

**列挙は `kite_shellhost.exe` の中だけ。** `IShellFolder::EnumObjects` は名前空間拡張の
DLL を呼び出し元プロセスに読み込ませる（「PC」を開くと iCloud の拡張が起き上がるのを
実測した）。P1-1 / P2-10 で追い出したものと性質が同じなので、3 つ目のホストとして同じ
仕組みに乗せてある。読み取りには 30 秒の制限がある ─ 名前空間拡張の列挙は中断できない
ので、返ってこない相手にできるのはホストごと捨てることだけ。

| ファイル | 役割 |
| --- | --- |
| `core/fs/VirtualPath.h` | `virtual:` の規則と 3 つの根、`..` の行き先（`tests/test_vfolder.cpp`） |
| `platform/win/VirtualNames.cpp` | Kite の綴りとシェルの解析名の相互変換。**ホストは前置を知らない** |
| `platform/win/ShellFolder.cpp` | `IShellFolder` の列挙本体。**`kite_shellhost.exe` だけがリンクする** |
| `platform/win/FolderHostClient.cpp` | ホストへの要求（時間制限あり、ワーカー間で直列化） |
| `platform/win/ShellFolder.cpp` の `ResolveItemsInFolder` | 「フォルダ + 解析名」から項目の PIDL を引き当てる |

**ごみ箱の項目は「どのフォルダの中の項目か」ごと渡して指す。** 消した項目の解析名は
隠された `$R` の写しのパスなので、そのまま解析するとごみ箱の項目ではなく**ただの
ファイル**が返り、その親はごみ箱ではないので「元に戻す」がどこにも現れない。要求に
フォルダを添えると（`shellhost::Request::container`）、ホストはそのフォルダを列挙して
解析名の一致する子の PIDL を組み立てる ─ 得られる絶対 PIDL の親はごみ箱そのものなので、
メニューもアイコンも今までどおりの道を通る。**PIDL をホスト側の表に置いて id を配る形は
採らなかった**（世代がずれた id は「別のファイルを消す」になる）。

**復元は `Alt+R`（`Cmd::Restore`）。** 実体はシェルの `undelete` 動詞で、右クリックの
メニューにも「元に戻す」が正しく並ぶ。設計上の判断は CLAUDE.md の「仮想フォルダ」と
「ごみ箱の項目を正しく指す」。

### P2-2. ZIP をフォルダとして開く — **S**（P2-1 で下地ができた）

ZIP はシェル名前空間拡張として見えるので、列挙も表示も P2-1 の経路がそのまま使える。
足りないのは入口の判断だけ ─ 一覧で `.zip` を開いたとき `shell_.Open()` に渡す

`OpenPath()` に渡す。**設定で切り替えられるようにすること** ─ 展開ソフトを入れている
人にとって、ZIP を開いた先はそのソフトであってほしい。

### P2-8. ネットワークの参照 — ✅ 完了

`\\192.168.1.5` のようにサーバーだけを指したパスが、その共有の一覧になる。
判定は `path::IsUncServer()`、列挙は `WinFileSystem::List` が `WNetOpenEnum` /
`WNetEnumResource` へ振り分ける（他の列挙と同じくワーカースレッド）。共有の親は
サーバー、というパスの読み方も揃えてあるので `..` と `Alt+↑` とパンくずがそのまま
効く。資格情報が要る相手には `Ctrl+Shift+L`（`Cmd::ConnectNetwork`）。
詳細は CLAUDE.md「ネットワークの参照」。

### P2-8b. ネットワーク全体の参照 — **M**

**混同しないこと。** P2-1 で開けるようになったのはエクスプローラーの「ネットワーク」
フォルダ（シェル名前空間）で、そこに並ぶのは主に SSDP で見つかった機器 ─ 実測で
15 秒待ってメディアレンダラーが 2 つ、という環境がある。ここで言っているのは
`\\` そのものを開いて SMB サーバーを列挙する話で、そちらはまだ入っていない。

`\\` そのものを開いて、ドメイン／ワークグループとその中のサーバーを列挙する話。
`WNetOpenEnum` に `lpRemoteName = nullptr` を渡し、返ってきたコンテナをもう 1 段
展開すればよい ─ **が、これはコンピューターブラウザーサービスに依存する**。
SMB1 とともに既定で無効化されて久しく、今の Windows では数十秒待たされた末に
空が返ることのほうが多い。**待たせて空を返す機能は、無い機能より悪い。**
入れるならタイムアウトと「探索中」の表示が先。

### P2-9. ドライブの安全な取り外し — **S**

サイドバーのコンテキストメニューから。`CM_Request_Device_Eject`。

### P2-10. 実アイコンとオーバーレイ — ✅ 完了

一覧とサイドバーがシェルの実アイコンを表示する。TortoiseGit・OneDrive・Google Drive
などのアイコンオーバーレイもそのまま乗る（`SHGFI_ADDOVERLAYS`）。

取得は `kite_shellhost.exe` の中だけ。オーバーレイハンドラは P1-1 で追い出したものと
性質が同じ in-proc DLL であり、加えて `SHGetFileInfo` は中断できないので、別プロセスで
あることが「返ってこないハンドラ」への唯一の対処になっている（CLAUDE.md
「シェル拡張の隔離」）。

| ファイル | 役割 |
| --- | --- |
| `core/app/IconProvider.h` | `IIconProvider` と `IconCache`。要求の重複排除と上限管理（`tests/test_iconcache.cpp`） |
| `platform/win/WinIconProvider.cpp` | ワーカースレッド。要求をまとめ、結果をレンダラへ渡す |

## 5. フェーズ 3 — 操作性（file pilot / filedini を超える部分）

### P3-1. コマンドパレット — **M**

全コマンドを絞り込み実行。`Cmd` テーブルと i18n ラベルがすでにあるので、
UI を足すだけで全操作が対象になる。キー割当を覚えていなくても到達できるようになり、
要件 12 の実用性が一段上がる。

`Alt+B` のブックマーク一覧（`core/app/BookmarkPicker`）が同じ形をしている ─
絞り込みと `↑↓` と `Enter` の 1 枚のオーバーレイ。パレットは「行が何を持つか」だけが
違うので、あの画面を一般化する形で入れられる。

### P3-2. 2 打鍵キーシーケンス — **S**

`Chord` は拡張できる形にしてある。`KeyMap` を「1 打鍵目で待機状態に入る」構造に変え、
`keys.ini` の記法を `Ctrl+K Ctrl+\` 形式に拡張する。

### P3-3. 一覧内インラインリネーム — **S**

現在はプロンプト行での編集。行内で直接編集できるほうがエクスプローラーに近い。
IME のキャレット位置追従はすでにあるので流用できる。

### P3-4. 型入力ジャンプ（type-ahead）— ✅ 完了

文字キーを押すと、その名前で始まる行へカーソルが飛ぶ。`Ctrl+F` の絞り込みとは別物で、
**行は 1 つも消えない** ─ 打った文字は 1.2 秒で消え、ステータス行に出る。同じ文字を
続けて打つと次の候補へ回り、打ち足せば絞り込まれる。

`Space` の衝突は「打っている最中かどうか」で捌いた ─ 打ちかけの文字列が無ければ
今までどおり選択のトグル、ある間は名前の一部として受け取る。`Backspace` と `Escape` も
同じ読み方で、打っている間だけ打ちかけの文字列のものになる。

**既定バインドは文字キー単独と `Shift+<文字>` を空けたまま残してある** ─ 修飾は必ず
`Ctrl` か `Alt` が付く。ここを埋めると、大文字小文字を畳んで飛ぶこの機能と
「`b` は項目へ、`B` は別の何かへ」という形で必ず食い違う。

判断はすべて `core/input/TypeAhead`（OS にも描画にも触れない）にあり、
`tests/test_typeahead.cpp` が端から端まで検証する。**時計は自分で読まない** ─
現在時刻は `App` が渡す。設計上の判断は [CLAUDE.md](../CLAUDE.md) の「型入力ジャンプ」に。

### P3-5. クイックアクセスのピン留め編集 — **S**

現在は既知フォルダの固定リスト。ブックマークと統合してもよい。

### P3-6. アドレスバーと、パス入力の補完 — ✅ 完了

アドレスバーは**タブバー直下のパンくずと同じ 1 行**。`Ctrl+L`（`Cmd::EditPath`）か、
パンくずの後ろの余白をクリックすると、その行がそのまま入力欄になる（開いた瞬間は
全選択、入力欄の外を押せばパンくずに戻る）。

打てば打った先のフォルダが候補に出る。1 文字ごとに絞られ、`Tab` / `↓` で採り、
`Shift+Tab` / `↑` で戻る。候補一覧はその行からフルパスで垂れ下がり、一覧に重ねて
描く。候補行のクリックはそのまま移動になる。`Escape` は先に候補を畳み、もう一度で
パンくずに戻る。

副産物として `Prompt` が選択範囲を持つようになったので、他の入力欄でも `Ctrl+A`・
`Shift+←→`・`Ctrl+←→`（パスの構成要素 1 つぶん）が同じように使える。

判断はすべて `core/input/PathComplete`（OS にも描画にも触れない）にあり、
`tests/test_pathcomplete.cpp` が端から端まで検証する。**列挙は自分でしない** ─
`App` が `DirectoryLoader` を通して取り、`SetListing()` で渡す。設計上の判断は
[CLAUDE.md](../CLAUDE.md) の「アドレスバー」「アドレスバーの補完」「入力欄の選択」に。

### P3-7. キー割当の GUI 設定 — ✅ 完了

`Ctrl+F1`（`Cmd::ShowKeySettings`）で設定画面を開く。全コマンドを一覧し、
`Enter` で変更、`Insert` で追加、`Delete` で解除、`Ctrl+R` で既定に戻す。
文字を打てばラベル・`keys.ini` の名前・現在の和音を横断して絞り込む。和音を他の
コマンドから奪った場合は、どのコマンドから奪ったかを画面に出す（黙って奪うと、
利用者は壊れたショートカットを探す羽目になる）。

判断はすべて `core/input/KeyEditor`（OS にも描画にも触れない）にあり、
`tests/test_keyeditor.cpp` が端から端まで検証する。UI 層は行を描いて入力を
渡すだけ。変更のたびに `keys.ini` を書き直すので、保存操作は無い。

### P3-8. 設定の GUI — ✅ 完了

`Ctrl+,`（`Cmd::ShowSettings`）で設定画面を開く。テーマ・言語・文字サイズ・サイドバー・
シェルアイコン・**タブバーの位置**・**新しいタブの位置**・新しいタブの既定
（隠しファイル／フォルダ先頭）を
`←→` か `Enter`、あるいはマウスで切り替える。変更はその場で効き、`settings.ini` に
即書き出す（保存操作は無い）。

メニューバーは足していない（「あえてやらないこと」）。`Ctrl+F1` のショートカット設定と
同じオーバーレイ・同じ行の作法にしてあり、判断は `core/app/SettingsEditor`（OS にも
描画にも触れない）が持つ。設計上の判断は [CLAUDE.md](../CLAUDE.md) の「設定画面」に。

### P3-9. セッションバーとタブバーの折り返し — ✅ 完了

どちらのバーも、収まらなくなった分を右端で切り捨てるのをやめ、行を増やすようにした。
切り捨てていた頃は、画面外のセッションとタブがクリックできず、省略された印も出なかった。
タブは下限の 70 px まで詰めてから折り返すので、1 行に収まっている限り見た目は変わらない。
併せて、9 個目以降のセッションチップが `Cmd::Session1 + 添字` でコマンド表の外を
指していた不具合も直した。詳細は [CLAUDE.md](../CLAUDE.md) の
「セッションバーとタブバーの折り返し」。

### P3-10. 縦置きのタブバー — ✅ 完了

`[ui] tab_bar_position = left`（設定画面「タブバーの位置」）で、タブバーをペインの左に
縦に立てられる。既定は今までどおり `top`。折り返しとスクロールの数え方は横置きと共通で、
描く向きだけが入れ替わる ─ ただし**縦置きは列を増やさずスクロールする**（2 列目を作ると
その幅がまるごと一覧から消える）。**バーの上のホイールでスクロールでき**、切り替えれば
アクティブなタブのところまで戻る。隠れているタブがあるときは列の右端に**つまみ**が出る
（掴めるようにするのは P3-11）。設計上の判断は [CLAUDE.md](../CLAUDE.md) の
「縦置きのタブバー」。

### P3-11. スクロールバーのドラッグと、長い一覧での選択の枠 — **S**

現在のスクロールバーは表示だけで掴めない ─ 一覧の脇のものも、縦置きタブバーの
つまみ（P3-10）も同じ。**掴めるようにするなら 2 本まとめて**で、隣り合った帯の片方だけが
動くのは学びにくい。掴めるようにすれば、その帯を
「選択の枠を引ける余白」から外している理由（`AppUi::BeginMarquee`）も消える。
そのうえで枠を一覧の端から引けるようにすると、全行が収まらない一覧でも枠が使える。
そこまで行くと**枠の自動スクロールが初めて意味を持つ** ─ ポインタが枠外で
止まったままではマウスイベントが来ないので、`WinWindow` 側に一定間隔のタイマーを
足して `AppUi` を叩く形になる（`kStatusTimerId` と同じ作り）。

## 8. あえてやらないこと

判断を蒸し返さないための記録。

- **リボン UI / コマンドバー。** キーボード駆動を主軸に据えたので不要。
- **ファイル操作の自前実装。** コピー・移動・削除はシェル（`SHFileOperation`）に
  委ねる。進捗表示・競合解決・ごみ箱連携を自前で書き直すのは、ファイラーが
  データを失う最も一般的な原因。
- **シェルアイコンの同期取得。** `SHGetFileInfo` は 1 行ごとにクラウドプロバイダを
  呼ぶ。要件 3・13 と正面から衝突する。アイコン自体は取るようになったが、
  UI スレッドからは決して呼ばない ─ 見えている行の分だけをまとめて
  `kite_shellhost.exe` に投げ、時間制限付きで待つ（P2-10）。
- **プラグインシステム。** 当面。サードパーティコードを自プロセスに入れるのは、
  P1-1 / P2-10 で追い出した方針と正面から逆行する。
- **サードパーティライブラリの導入。** 起動時間・配布サイズ・ビルドの単純さを
  優先する。テストハーネスを自作しているのもこの方針の一貫。

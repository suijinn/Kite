## 3. フェーズ 1 — 安定性（最優先）

要件 13 の残課題と、常用に入る前に潰しておくべきもの。

### P1-1. シェル拡張の別プロセス化 `kite_shellhost.exe` — ✅ 完了

`IContextMenu` のハンドラ（Box、Google Drive、7-Zip、TortoiseGit …）は
`kite_shellhost.exe` の中だけで動く。拡張が確保したメモリを壊しても、裏でスレッドを
立てて落ちても、失われるのはメニュー 1 回分とホストプロセスだけ。次の要求で黙って
起動し直す。これで要件 13 が埋まった。

構成:

| ファイル | 役割 |
| --- | --- |
| `platform/win/ShellHostProtocol.h` | 交換する書式。Windows 非依存で、`tests/test_hostproto.cpp` が直接検証する |
| `platform/win/ShellPipe.cpp` | 名前付きパイプのフレーム送受信。待機中も両側がメッセージを回す |
| `platform/win/ShellHostClient.cpp` | 起動・接続・要求（`kite.exe` 側） |
| `platform/win/ShellMenu.cpp` | `IContextMenu` 本体。**`kite_shellhost.exe` だけがリンクする** |
| `tools/shellhost/main.cpp` | ホストの入口。隠しウィンドウとメッセージポンプ |

`IShellIntegration`（`core/app/Host.h`）が渡すのは相変わらずパスと座標だけ。
戻り値が `void` から `bool` になり、メニューを出せなかったことを status 行に
出せるようになった以外、core / ui 側の変更は無い。

設計上の判断は CLAUDE.md の「シェル拡張の隔離」に、残っている制限は同「現時点の
弱点」に書いてある。

### P1-2. 元に戻す（Ctrl+Z）— **S**

削除・移動・コピーはすでに `FOF_ALLOWUNDO` 付きで実行しているので、シェルの
Undo スタックには積まれている。`Cmd::Undo` を足し、シェルの Undo を呼ぶ配線だけ。
Kite 自前の履歴を持つか、シェル任せにするかは要判断（後者が安全）。

主な変更: `core/input/Commands.h`、`App::Execute`、`IShellIntegration` に 1 メソッド。

### P1-3. 単一インスタンス化 — **S**

エクスプローラーの代替として使うなら、フォルダをダブルクリックするたびに新しい
ウィンドウが増えるのは困る。起動時に名前付きミューテックスで既存インスタンスを検出し、
既存ウィンドウへパスを送って新規タブで開く。`WM_COPYDATA` で足りる。

主な変更: `src/main_win.cpp`、`platform/win/WinWindow.cpp`。

### P1-4. エラー処理の網羅 — **M**

現状は「読めなかった」ことは表示できるが、以下が未検証。
アクセス拒否フォルダ、ロック中ファイルのリネーム、260 文字超のパス
（`ToExtendedPath` は実装済みだが未テスト）、列挙中のドライブ切断、
オフラインのクラウドフォルダ。テストを先に書いてから潰す。

主な変更: `platform/win/WinFileSystem.cpp`、`tests/`。

### P1-5. CI — **S**

GitHub Actions で Windows ランナー上の `cmake --preset release` + `ctest`。
`clang-format --dry-run --Werror` も同時に回す。

## 4. フェーズ 2 — エクスプローラー機能パリティ

要件 6 を埋める。ここまで来ると「常用してエクスプローラーを無効化できる」水準。

### P2-1. 仮想フォルダ（「PC」「ごみ箱」「ネットワーク」）— **L**

`IFileSystem` の実装をもう 1 つ（`WinShellFileSystem`）用意し、パスが
実ファイルシステムでない場合だけ `IShellFolder` 経由で列挙する。
実 FS の高速経路は一切汚さないのが要点。`fs::Entry` に「シェル項目である」印と
PIDL を持たせる必要があるため、`core/fs/FileSystem.h` に不透明ハンドルを 1 つ足す。

### P2-2. ZIP をフォルダとして開く — **M**

P2-1 の仕組みに乗る（ZIP はシェル名前空間拡張として見える）。P2-1 の後なら追加は小さい。

### P2-3. 検索 — **M**

現フォルダ以下の再帰インクリメンタル検索。ワーカースレッドで列挙し、
結果を仮想的な一覧としてタブに表示する。Windows Search インデックスは使わず
自前で歩く（インデックス未作成のフォルダでも効くほうが実用的）。

主な変更: `core/fs/` に `SearchJob`、`Tab` に「検索結果モード」、`Cmd::Search`。

### P2-4. サムネイル — **M**（P2-10 で下地ができた）

`IThumbnailCache` / `IShellItemImageFactory` を**必ず別スレッド**で呼ぶ。
`ui::Renderer::DrawIcon` と `IIconProvider`、ホストとの画素のやりとりは P2-10 で
できているので、要求の種別とサイズを足して同じ経路に乗せる。
クラウドのプレースホルダに対しては要求しないこと（ダウンロードが走る）。

### P2-10. 実アイコンとオーバーレイ — ✅ 完了

一覧とサイドバーがシェルの実アイコンを表示する。TortoiseGit・OneDrive・Google Drive
などのアイコンオーバーレイもそのまま乗る（`SHGFI_ADDOVERLAYS`）。

取得は `kite_shellhost.exe` の中だけで行う。オーバーレイハンドラはサードパーティの
in-proc DLL であり、P1-1 で追い出したものと性質が同じため。加えて `SHGetFileInfo` は
中断できないので、別プロセスであることが「返ってこないハンドラ」への唯一の対処に
なっている（詳細は CLAUDE.md の「シェル拡張の隔離」）。

| ファイル | 役割 |
| --- | --- |
| `core/app/IconProvider.h` | `IIconProvider` と `IconCache`。要求の重複排除と上限管理。`tests/test_iconcache.cpp` が検証 |
| `platform/win/WinIconProvider.cpp` | ワーカースレッド。要求をまとめ、結果をレンダラへ渡す |
| `platform/win/IconHostClient.cpp` | ホストへの要求（時間制限あり） |
| `platform/win/ShellIcons.cpp` | `SHGetFileInfo` 本体。**`kite_shellhost.exe` だけがリンクする** |
| `platform/win/ShellHostProcess.cpp` | ホスト 1 つ分の起動・接続・後始末。メニュー用とアイコン用が共有 |

`[ui] shell_icons = false` でシェルを一切呼ばない従来の描画に戻せる。

### P2-5. 表示形式の切替 — **M**

詳細（現行）／一覧／中アイコン／大アイコン。`ui/views/` に描画モードを足す。
P2-4 のサムネイルとセットで意味を持つ。

### P2-6. 列のカスタマイズ・幅調整・グループ化 — **M**

現在は列幅固定・列固定。`ViewState` に列定義を持たせ、ヘッダのドラッグで幅変更、
`settings.ini` に永続化。

### P2-7. プレビューウィンドウ — **M**

`IPreviewHandler` を使う場合はサードパーティコードが再び自プロセスに入るため、
**P1-1 で作った `kite_shellhost.exe` に相乗りさせる**のが筋。`ShellHostProtocol.h` に
要求の種別を足し、プレビューはホスト側のウィンドウを Kite の子として貼るか、
ビットマップを共有メモリで受け取る形になる。

### P2-8. ネットワークの参照 — **M**

`WNetOpenEnum` / `WNetEnumResource` でサーバーと共有を列挙。
必ずワーカースレッドで、タイムアウト付きで。

### P2-9. ドライブの安全な取り外し — **S**

サイドバーのコンテキストメニューから。`CM_Request_Device_Eject`。

## 5. フェーズ 3 — 操作性（file pilot / filedini を超える部分）

### P3-1. コマンドパレット — **M**

全コマンドを絞り込み実行。`Cmd` テーブルと i18n ラベルがすでにあるので、
UI を足すだけで全操作が対象になる。キー割当を覚えていなくても到達できるようになり、
要件 12 の実用性が一段上がる。

### P3-2. 2 打鍵キーシーケンス — **S**

`Chord` は拡張できる形にしてある。`KeyMap` を「1 打鍵目で待機状態に入る」構造に変え、
`keys.ini` の記法を `Ctrl+K Ctrl+\` 形式に拡張する。

### P3-3. 一覧内インラインリネーム — **S**

現在はプロンプト行での編集。行内で直接編集できるほうがエクスプローラーに近い。
IME のキャレット位置追従はすでにあるので流用できる。

### P3-4. 型入力ジャンプ（type-ahead）— **S**

文字キーを押すと該当項目へジャンプ。`Ctrl+F` の絞り込みとは別機能。
`Space` の選択トグルとの衝突をどう捌くか要検討。

### P3-5. クイックアクセスのピン留め編集 — **S**

現在は既知フォルダの固定リスト。ブックマークと統合してもよい。

### P3-6. パス入力の補完 — **S**

`Ctrl+L` のプロンプトでのインクリメンタル補完。

### P3-7. キー割当の GUI 設定 — ✅ 完了

`Ctrl+F1`（`Cmd::ShowKeySettings`）で設定画面を開く。全コマンドを一覧し、
`Enter` で変更、`Insert` で追加、`Delete` で解除、`Ctrl+R` で既定に戻す。
文字を打てばラベル・`keys.ini` の名前・現在の和音を横断して絞り込む。

判断はすべて `core/input/KeyEditor`（OS にも描画にも触れない）にあり、
`tests/test_keyeditor.cpp` が端から端まで検証する。UI 層は行を描いて入力を
渡すだけ。変更のたびに `keys.ini` を書き直すので、保存操作は無い。

和音を他のコマンドから奪った場合は、どのコマンドから奪ったかを画面に出す
（`KeyMap::Bind` が黙って奪う仕様のままだと、利用者は壊れたショートカットを
探す羽目になる）。

### P3-8. スクロールバーのドラッグと、長い一覧での選択の枠 — **S**

現在のスクロールバーは表示だけで掴めない。掴めるようにすれば、その帯を
「選択の枠を引ける余白」から外している理由（`AppUi::BeginMarquee`）も消える。
そのうえで枠を一覧の端から引けるようにすると、全行が収まらない一覧でも枠が使える。
そこまで行くと**枠の自動スクロールが初めて意味を持つ** ─ ポインタが枠外で
止まったままではマウスイベントが来ないので、`WinWindow` 側に一定間隔のタイマーを
足して `AppUi` を叩く形になる（`kStatusTimerId` と同じ作り）。

## 6. フェーズ 4 — 性能とメモリ

### P4-1. メモリ削減（約 66 MB → 40 MB 台）— **M**

内訳の実測がまだ。まず何が食っているかを確定させる。想定される手当:
D3D11 デバイスの遅延生成と非アクティブ時の解放、`fs::Entry` の SoA 化
（現在は 1 件あたり `std::string` を持つ）、DirectWrite のフォントキャッシュ調整。
**先に計測すること。** 推測で削らない。

### P4-2. 巨大ディレクトリ対応 — **M**

10 万件クラスでの列挙・ソート・描画。列挙結果のストリーミング表示
（全件揃う前に描き始める）と、ソートの並列化。

### P4-3. 起動時間の実測と短縮 — **S**

現状の計測は `Start-Process` 経由でプロセス生成込みのため誤差が大きい。
アプリ内に計測点を仕込んで内訳（DLL ロード / D3D 初期化 / 設定読み込み / 初回列挙）を出す。

## 8. あえてやらないこと

判断を蒸し返さないための記録。

- **リボン UI / コマンドバー。** キーボード駆動を主軸に据えたので不要。
- **ファイル操作の自前実装。** コピー・移動・削除はシェル（`SHFileOperation`）に
  委ねる。進捗表示・競合解決・ごみ箱連携を自前で書き直すのは、ファイラーが
  データを失う最も一般的な原因。
- **シェルアイコンの同期取得。** `SHGetFileInfo` は 1 行ごとにクラウドプロバイダを
  呼ぶ。要件 3・13 と正面から衝突する。アイコン自体は取るようになったが、
  UI スレッドからは決して呼ばない ─ 見えている行の分だけをまとめて
  `kite_shellhost.exe` に投げ、時間制限付きで待つ（P2-10）。
- **プラグインシステム。** 当面。サードパーティコードを自プロセスに入れる方針は
  P1-1 で減らそうとしている最中であり、逆行する。
- **サードパーティライブラリの導入。** 起動時間・配布サイズ・ビルドの単純さを
  優先する。テストハーネスを自作しているのもこの方針の一貫。

## 9. 次にやるべきこと

常用可能なところまでの最短経路（P1-1 は完了済み）:

1. **P1-3 単一インスタンス化** — エクスプローラーの既定を置き換えるなら必須級。小さい。
2. **P1-2 元に戻す（Ctrl+Z）** — 削除・移動を取り消せないのは常用の心理的障壁。小さい。
3. **P2-1 仮想フォルダ** — 「PC」が開けないと日常運用で詰まる。
4. **P3-1 コマンドパレット** — ここまでの機能増を、覚えなくても使える形にする。
   P3-7 の設定画面（`core/input/KeyEditor`）が絞り込み付きコマンド一覧そのものなので、
   実行する経路を足すだけで済む。
